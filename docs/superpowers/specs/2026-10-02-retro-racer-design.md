# Retro Racer 설계 문서

작성일: 2026-10-02

## 1. 목적

Retro Racer는 브라우저에서 실행하는 유사 3D 아케이드 레이싱 게임입니다. 아웃런 계열 게임처럼 차량 뒤에서 도로를 바라보는 시점을 사용하며, 제한 시간 안에 체크포인트를 통과하여 결승점까지 도달하는 것이 목표입니다. 재미를 위한 개인 프로젝트이므로, 짧은 시간에 한 판을 끝낼 수 있고 반복해서 기록에 도전할 수 있어야 합니다.

### 성공 기준

- `npm run dev`로 실행한 뒤 키보드만으로 타이틀 화면에서 주행, 결과 화면까지 한 판을 진행할 수 있습니다.
- 커브와 언덕이 있는 도로가 초당 60프레임에 가깝게 끊김 없이 그려집니다.
- 체크포인트를 통과하면 남은 시간이 늘어나고, 배경 테마가 다음 구간의 테마로 전환됩니다.
- 엔진음이 속도에 따라 달라지고, 충돌·체크포인트·니트로에 효과음이 재생됩니다.
- 최고 기록이 브라우저를 다시 열어도 유지됩니다.
- `npm test`와 `npm run build`가 오류 없이 통과합니다.

### 범위에서 제외하는 것

- 모바일 터치 조작과 게임패드 지원
- AI 경쟁 차량과 순위 경쟁
- 코스 선택, 차량 선택, 난이도 선택
- 배경 음악
- 이미지 파일과 음원 파일 (모든 그림과 소리는 코드로 생성합니다)

## 2. 기술 구성

- Vite + TypeScript + Vitest를 사용하며, 형제 프로젝트인 `powder-lab`과 동일한 구성을 따릅니다.
- UI 프레임워크는 사용하지 않습니다. 화면 전체를 프레임마다 Canvas 2D로 다시 그리는 게임이므로, 타이틀·HUD·결과 화면도 캔버스에 직접 그립니다.
- 실행 의존성은 없으며, 개발 의존성은 `typescript`, `vite`, `vitest`입니다.
- 저장소 위치는 `game-projects/retro-racer/`이며 독립된 git 저장소로 관리합니다.

## 3. 게임 규칙

### 조작

| 키 | 동작 |
|---|---|
| ← / → (또는 A / D) | 좌우 조향 |
| ↑ (또는 W) | 가속 |
| ↓ (또는 S) | 브레이크 |
| Space | 니트로 사용 |
| Enter | 게임 시작, 결과 화면에서 재시작 |
| M | 소리 켜기·끄기 |

### 주행

- 가속 키를 누르면 최고 속도까지 가속하고, 아무 키도 누르지 않으면 서서히 감속합니다. 브레이크는 자연 감속보다 빠르게 속도를 줄입니다.
- 조향 속도는 현재 속도에 비례합니다. 정지 상태에서는 좌우로 움직이지 않습니다.
- 커브 구간에서는 속도와 커브 강도에 비례하여 차량이 커브 바깥쪽으로 밀립니다. 플레이어는 반대 방향으로 조향하여 차선을 유지해야 합니다.
- 차량이 도로 밖으로 나가면 속도가 최고 속도의 약 1/4까지 빠르게 줄어듭니다.
- 차량의 좌우 위치는 도로 폭의 2배 범위를 넘지 못하도록 제한합니다.

### 충돌

- 도로 밖의 길가 사물(나무, 선인장, 표지판 등)과 부딪히면 속도가 거의 0으로 줄어듭니다.
- 앞서 가는 일반 차량의 뒤를 들이받으면, 플레이어의 속도가 그 차량의 속도보다 낮은 값으로 줄어듭니다.
- 충돌로 게임이 즉시 끝나지는 않습니다. 충돌에 따른 불이익은 시간 손실입니다.

### 일반 차량

- 코스 전체에 일반 차량 약 40대를 배치합니다. 각 차량은 고정된 차선과 플레이어의 최고 속도보다 낮은 일정한 속도로 주행합니다.
- 차량 배치는 고정된 시드를 사용하는 난수로 결정하므로, 매 판의 배치가 동일합니다. 플레이어가 코스를 익혀서 기록을 단축할 수 있도록 하기 위한 결정입니다.

### 니트로

- 니트로 게이지는 0에서 100 사이의 값이며, 시작할 때는 0입니다.
- 일반 차량을 가깝게 스치면서 추월하면(충돌하지 않고 좌우 간격이 좁은 상태로 지나가면) 게이지가 25만큼 증가합니다. 충돌 없이 일반적으로 추월하면 5만큼 증가합니다.
- 게이지가 30 이상일 때 Space를 누르면 니트로가 작동합니다. 작동하는 동안 게이지가 초당 약 33씩 줄어들고, 최고 속도와 가속도가 약 1.3배로 높아집니다. 게이지가 0이 되거나 충돌하면 니트로가 종료됩니다.

### 시간과 체크포인트

- 시작할 때 남은 시간은 60초입니다.
- 코스는 5개 구간으로 나뉘며, 구간 경계에 체크포인트 4개가 있고 마지막 구간의 끝이 결승점입니다.
- 체크포인트를 통과하면 남은 시간에 30초가 추가됩니다.
- 남은 시간이 0이 되면 가속할 수 없게 되고, 차량이 완전히 멈추면 실패로 종료합니다.
- 결승점을 통과하면 완주로 종료합니다.

### 기록

- 완주했을 때는 총 주행 시간을 기록하며, 짧을수록 좋은 기록입니다.
- 실패했을 때는 도달한 거리를 기록하며, 멀수록 좋은 기록입니다.
- 최고 완주 시간과 최장 도달 거리를 `localStorage`에 저장합니다. 완주 기록이 하나라도 있으면 타이틀과 결과 화면에 완주 시간을 우선하여 표시합니다.
- `localStorage`를 사용할 수 없는 환경에서는 오류를 내지 않고 기록 저장만 생략합니다.

## 4. 코스와 테마

코스는 직선·커브·언덕 조각을 순서대로 이어 붙여 정의하며, 각 조각은 진입·유지·이탈 길이와 커브 강도, 높이 변화를 가집니다. 코스를 생성하는 함수가 이 정의를 길이 200 단위의 구간(segment) 배열로 변환합니다. 전체 길이는 최고 속도로 달렸을 때 약 2분 30초가 걸리는 정도로 설정합니다.

| 구간 | 테마 | 하늘 | 지면 | 길가 사물 | 도로 특성 |
|---|---|---|---|---|---|
| 1 | 해변 | 밝은 하늘색 | 모래색 | 야자수 | 완만한 커브 |
| 2 | 사막 | 주황빛 노을 | 황토색 | 선인장, 바위 | 긴 직선과 언덕 |
| 3 | 숲 | 옅은 청록색 | 짙은 초록색 | 침엽수 | 연속되는 급커브 |
| 4 | 야간 도시 | 짙은 남색 | 어두운 회색 | 가로등, 빌딩 | 차량이 많은 직선과 커브 |
| 5 | 새벽 | 분홍빛 여명 | 연한 초록색 | 표지판, 깃발 | 결승점으로 이어지는 완만한 구간 |

- 테마는 하늘 색 2개(위·아래 그라데이션), 지면 색, 도로 색, 연석 색, 차선 색, 안개 색과 길가 사물 종류로 구성합니다.
- 체크포인트를 통과한 뒤 약 2초에 걸쳐 색을 선형 보간하여 다음 테마로 전환합니다. 길가 사물은 구간에 고정되어 있으므로 별도의 전환 처리가 필요하지 않습니다.
- 체크포인트와 결승점 위치에는 도로를 가로지르는 아치형 구조물을 그립니다.

## 5. 구조

게임 로직과 그리기를 분리합니다. `src/game/` 아래의 모듈은 DOM과 캔버스에 의존하지 않는 순수 함수와 데이터로 작성하여 단위 테스트로 검증합니다.

```
retro-racer/
  index.html
  src/
    main.ts            게임 루프, 화면 전환, 모듈 연결
    input.ts           키 입력 상태 관리
    audio.ts           Web Audio 엔진음과 효과음
    storage.ts         최고 기록 저장과 불러오기
    style.css
    game/
      constants.ts     속도·도로 폭·시간 등 조정값
      types.ts         공용 타입
      track.ts         코스 정의를 구간 배열로 변환
      themes.ts        테마 정의와 색 보간
      player.ts        가속, 조향, 원심력, 도로 이탈, 니트로
      traffic.ts       일반 차량 배치, 이동, 충돌·추월 판정
      race.ts          타이머, 체크포인트, 상태 전환, 기록 계산
      step.ts          한 시간 단계의 전체 갱신
    render/
      projection.ts    월드 좌표를 화면 좌표로 투영
      road.ts          도로 구간, 연석, 차선
      background.ts    하늘, 태양·달, 원경
      sprites.ts       길가 사물, 일반 차량, 플레이어 차량
      hud.ts           속도, 남은 시간, 니트로 게이지, 진행도
      screens.ts       타이틀 화면과 결과 화면
      render.ts        위 모듈을 순서대로 호출
  tests/
```

### 주요 인터페이스

- `buildTrack(): Track`은 구간 배열, 체크포인트 위치, 구간별 테마 번호, 길가 사물 목록을 담은 코스를 반환합니다.
- `GameState`는 진행 단계(`title`, `racing`, `finished`, `timeUp`), 플레이어 상태(위치, 좌우 위치, 속도, 니트로), 일반 차량 목록, 남은 시간, 경과 시간, 통과한 체크포인트 수, 이번 단계에서 발생한 사건 목록을 가집니다.
- `step(state, input, track, dt): GameState`는 입력과 고정된 시간 간격을 받아서 다음 상태를 반환합니다. 충돌, 체크포인트 통과, 근접 추월, 니트로 시작과 같은 사건은 `events` 배열에 기록합니다.
- `render(ctx, state, track, alpha)`는 상태를 읽어서 화면을 그리며, 상태를 변경하지 않습니다.
- `audio.update(state)`는 속도에 맞게 엔진음을 조정하고, `events`에 기록된 사건에 해당하는 효과음을 재생합니다.

### 게임 루프

`main.ts`는 `requestAnimationFrame`으로 루프를 실행하고, 누적된 시간을 1/60초 단위로 나누어 `step`을 호출합니다. 탭이 비활성화되었다가 돌아왔을 때 한꺼번에 많은 단계가 실행되지 않도록, 한 프레임에 누적되는 시간을 0.1초로 제한합니다.

### 그리기 방식

- 카메라 위치에서 시작하여 앞쪽 약 200개 구간을 투영하고, 먼 구간부터 가까운 구간 순서가 아니라 가까운 구간부터 그리면서 이미 그려진 화면 높이보다 낮은 구간은 생략합니다. 이렇게 처리하면 언덕 뒤에 있는 도로가 가려집니다.
- 커브는 구간마다 화면상의 가로 위치를 누적하여 이동시키는 방식으로 표현합니다.
- 길가 사물과 차량은 먼 것부터 가까운 것 순서로 그리며, 해당 구간의 가림 높이를 기준으로 아래쪽을 잘라냅니다.
- 모든 사물은 사각형·삼각형·원과 같은 도형을 조합하여 그립니다.
- 캔버스의 내부 해상도는 가로 1024, 세로 576으로 고정하고, CSS로 창 크기에 맞게 비율을 유지하며 확대합니다.

### 소리

- 엔진음은 톱니파 발진기 2개와 저역 통과 필터로 구성하고, 속도에 비례하여 주파수를 조정합니다. 니트로가 작동하는 동안에는 주파수와 음량을 높입니다.
- 효과음(충돌, 체크포인트, 니트로 시작, 시간 경고, 완주)은 짧은 발진기 음과 잡음을 조합하여 만듭니다.
- 브라우저의 자동 재생 제한 때문에, `AudioContext`는 Enter로 게임을 처음 시작할 때 생성합니다.
- Web Audio를 사용할 수 없으면 소리 없이 게임을 진행합니다.

## 6. 테스트

Vitest로 다음 항목을 검증합니다.

- `track`: 구간 수와 전체 길이, 체크포인트가 4개이고 위치가 오름차순인지, 구간별 테마 번호가 올바른지 확인합니다.
- `player`: 가속과 최고 속도 제한, 자연 감속과 브레이크, 속도에 비례하는 조향, 커브에서 바깥쪽으로 밀리는 동작, 도로 이탈 시 감속, 좌우 위치 제한, 니트로 작동 조건과 게이지 소모를 확인합니다.
- `traffic`: 시드가 같으면 배치가 동일한지, 추돌했을 때 속도가 줄어드는지, 근접 추월과 일반 추월에서 게이지가 올바르게 증가하는지, 같은 차량을 두 번 계산하지 않는지 확인합니다.
- `race`: 타이머 감소, 체크포인트 통과 시 시간 추가, 시간 초과 후 정지하면 실패로 전환되는지, 결승점 통과 시 완주로 전환되는지, 기록 비교가 올바른지 확인합니다.
- `themes`: 색 보간의 양 끝 값과 중간 값을 확인합니다.
- `projection`: 카메라 앞에 있는 점의 화면 좌표와 크기 비율이 거리에 반비례하는지 확인합니다.
- `storage`: 저장과 불러오기, 손상된 값이 저장되어 있을 때 기본값으로 대체되는지 확인합니다.

그리기와 소리는 자동 테스트 대상에서 제외하며, 개발 서버를 실행하여 브라우저에서 직접 플레이하면서 확인합니다.
